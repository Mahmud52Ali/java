# CourseHub — лабораторная 8

Задания 1–7 по Stream API. `Main` запускает каждую демонстрацию отдельным вызовом.

Автор: Горбачев Д.В.

Отчёт: [PDF](output/pdf/Горбачев_ДВ_Отчет_практическая_работа_8.pdf) · [DOCX](output/docx/Горбачев_ДВ_Отчет_практическая_работа_8.docx)

## Запуск

Нужны JDK 21+ и Gradle.

```sh
gradle run
```

## Реализация

| № | Класс | Что проверять |
|---|---|---|
| 1 | `Task01DeterministicSorting` | Сортировка по уровню, длительности, коду и ID; одинаковый порядок при перестановке источника |
| 2 | `Task02FlatMapTopics` | `flatMap`, нормализация уникальных тем и обратный индекс тема → курсы |
| 3 | `Task03ReduceIdentity` | Сумма `CourseDuration`, identity и ассоциативность `plus` |
| 4 | `Task04CollectorsSummary` | Группировка по уровню и средняя длительность за один проход |
| 5 | `Task05OptionalResult` | Поиск самого длинного курса и fallback без `Optional.get()` |
| 6 | `Task06CustomCollector` | Count/sum/min/max, combiner на parallel stream и сравнение с `summarizingLong` |
| 7 | `Task07OnePassReport` | Один проход событий, уникальные студенты, completion rate, top-3, уровни и аномалии |

В задании 7 считаются все различные положительные ID студентов из входного потока; записи на неизвестные курсы отмечаются как аномалии и не входят в статистику курсов. Top-3 означает три курса с наибольшим числом уникальных записей; при равенстве порядок задаёт код курса. Список примеров аномалий ограничен десятью, а их общее количество и распределение по типам считаются полностью. Точный подсчёт уникальных студентов и повторных записей требует хранить множества ID студентов и пар «студент—курс»; сами события не копируются. Для такого многосоставного однопроходного отчёта используется обычный цикл.
