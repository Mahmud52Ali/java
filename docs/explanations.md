# Объяснения к лабораторной 3

## 1. List

Регистрация равна другой по паре studentId/courseId. Список хранит порядок и повторы; дубликаты в небольшом примере ищутся через contains, что даёт O(n²). Для индексного чтения выбираем ArrayList: get — O(1), полный проход по индексам — O(n). У LinkedList get — O(n), такой проход — O(n²). For-each у обоих — O(n). Время измеряется на одинаковых данных вне заполнения и вывода; это учебное измерение с предварительным запуском, не микробенчмарк и не гарантия результатов на другой JVM.

## 2. Set

LinkedHashSet убирает дубликаты и сохраняет порядок первого появления. Хеш сужает поиск, equals подтверждает равенство: одинаковый хеш не означает равенство. CourseCode — record, поэтому оба метода учитывают value; разные объекты с одним кодом считаются повтором. Поиск и добавление ожидаемо O(1) при хорошем распределении хешей, дополнительные связи требуют памяти для порядка.

## 3. Map

Ключ — CourseId, значение — Course. get возвращает значение или null; containsKey проверяет присутствие ключа. putIfAbsent добавляет готовое значение, computeIfAbsent вызывает функцию создания, только если значения нет. Оба считают отображение в null отсутствующим; у нашего индекса null-значений нет. Повторный ID вызывает исключение через результат putIfAbsent, исходный курс сохраняется. LinkedHashMap выбран для порядка вывода.

## 4. Queue

ArrayDeque даёт FIFO при добавлении в конец и извлечении из начала. add/offer добавляют; при заполненной ограниченной очереди add выбрасывает исключение, offer возвращает false. ArrayDeque расширяется автоматически. remove/poll возвращают и удаляют первого; при пустоте исключение/null. element/peek возвращают первого без удаления; при пустоте исключение/null. Null в ArrayDeque запрещён, поэтому null от poll/peek означает пустоту. Операции на концах амортизированно O(1).

## 5. Удаление

Enhanced for использует итератор. Прямое удаление из ArrayList во время обхода в примере вызывает ConcurrentModificationException даже в одном потоке; уже выполненное удаление не отменяется. Обнаружение не гарантировано во всех ситуациях. iterator.remove удаляет последний элемент next и согласует обход; removeIf удаляет по условию. Копия требует O(n) дополнительной памяти, а многократные удаления из оригинала могут оставаться дорогими.

## 6. Result<T>

Инвариант: присутствует ровно одно — ненулевое значение или непустая причина ошибки. Конструктор закрыт, создание через success/failure. Нельзя читать значение отказа или ошибку успеха. Result<Course> и Result<String> несовместимы, raw types не используются. Примеры ошибочного присваивания оставлены в блоке комментария Task06GenericResult.

## 7. Generic-методы

firstOrThrow возвращает первый элемент, пустой список вызывает NoSuchElementException. swap проверяет оба индекса до изменения и требует список с поддержкой set. indexBy получает ключ через Function<T,K>, запрещает null-элементы/ключи и явно отвергает повтор. LinkedHashMap сохраняет входной порядок. Для нескольких регистраций одного студента нужен другой контракт: Map<Long,List<Registration>>.

## 8. Comparable

max требует T extends Comparable<? super T>: сравнение может быть реализовано для самого типа или его предка. Если Parent реализует Comparable<Parent>, его наследник Child подходит под это ограничение. Метод проверен на Integer, String и CourseId; у последнего сравниваются long через Long.compare без переполнения вычитания. Null и пустой список запрещены. Максимум по строкам лексикографический, а не по длине. Обход O(n), дополнительная память O(1).

## 9. PECS

Producer extends, consumer super. Из List<? extends Course> читается Course, но добавление конкретного объекта запрещено: реальный список может иметь неизвестный более узкий тип. Из List<? super Course> гарантированно читается только Object, потому что реальный список может быть List<Object>; добавлять Course и наследников безопасно. Copy добавляет ссылки на существующие объекты, не переносит их и не очищает источник. Получатель должен поддерживать add; источник и получатель в примерах различны.

## 10. Ключ

Course сравнивается только по ID, внешнего изменения ID нет. CompletedHours не влияет на equals/hashCode, поэтому прогресс можно менять после помещения в HashSet/HashMap. В BrokenHashCourse прогресс намеренно включён в хеш: после изменения get/contains не находят элемент, хотя размер остаётся прежним. Ключи и поля равенства/хеша должны быть стабильны; нарушение также может дать разные хеши равных по ID объектов.

## 11. Выбор коллекций

| Сценарий | Интерфейс и реализация | Главные операции | Память и порядок |
|---|---|---|---|
| Каталог по ID | Map / HashMap | get, put: ожидаемо O(1) | O(n), корзины и узлы; порядок не гарантирован |
| Leaderboard | NavigableMap / TreeMap, балл → List участников | Группа по баллу: O(log n), добавление в её ArrayList: амортизированно O(1) | O(n + участников); дерево и ссылки, баллы по убыванию, равные баллы не теряются |
| Очередь | Queue / ArrayDeque | offer, poll, peek: амортизированно O(1) | O(n), массив с запасом вместимости; FIFO |
| Уникальные теги с порядком | Set / LinkedHashSet | add, contains: ожидаемо O(1) | O(n), хеш-таблица и связи порядка |
| Диапазонный поиск | NavigableMap / TreeMap | get/put: O(log n); поиск и обход k результатов: O(log n + k) | O(n), узлы дерева; порядок по ID |
| Доступ по индексу | List / ArrayList | get: O(1), добавление в конец: амортизированно O(1), удаление из середины: O(n) | O(n), массив с запасом; порядок позиций |

Для хеш-коллекций оценка зависит от распределения хешей: много коллизий замедляет операции. У subMap результат — представление диапазона; указанная сложность включает получение данных из него.

## 12. Repository<ID,T>

Save принимает ID и сущность отдельно; повторный ID заменяет значение, не создавая вторую запись. LinkedHashMap даёт порядок добавления. FindById возвращает Optional, deleteById — факт удаления. Null для ID и сущности запрещён. FindAll возвращает неизменяемую копию списка: изменение репозитория не меняет старый список, но сами сущности не клонируются. get/save/delete ожидаемо O(1), findAll — O(n).

## 13. Индекс тегов

Map<Tag,Set<CourseId>> реализован через LinkedHashMap и LinkedHashSet: уникальность, быстрый поиск и воспроизводимый порядок. Повторное добавление курса заменяет его теги. Удаление проходит по наборам и убирает пустые; отдельный обратный индекс не нужен. Пересечение retainAll сохраняет только ID, присутствующие под каждым тегом. Неизвестный тег и пустой запрос дают пустое множество. Snapshot копирует и закрывает от изменений и map, и вложенные set.

## 14. LRU

LinkedHashMap с accessOrder=true хранит от самого старого к самому недавнему. Успешный get и put обновляют недавность; промах её не меняет. При превышении положительной ёмкости удаляется первый ключ. Null-ключи/значения запрещены, get возвращает Optional. Сценарий: A,B → get(A): B,A → put(C): A,C, вытеснен B; обновление A: C,A → put(D): A,D, вытеснен C. CourseId неизменяем и имеет стабильные equals/hashCode. get/put ожидаемо O(1), память O(ёмкости), снимок ключей O(ёмкости).

## 15. Prerequisites

Ребро course → prerequisite хранится в Map<T,Set<T>>. Обе вершины добавляются заранее; неизвестная вершина отвергается до изменения графа. LinkedHashMap/LinkedHashSet фиксируют порядок вставки, поэтому одинаковый ввод даёт одинаковый результат. DFS сначала обрабатывает prerequisites, затем курс; встреча вершины текущего пути даёт замкнутый диагностический цикл. При цикле частичный порядок не возвращается. Пустой граф даёт пустой допустимый порядок, повторное ребро не дублируется. Время O(V+E), память со снимком графа O(V+E), стек DFS O(V). Тип вершин обобщённый; ключи должны иметь стабильное равенство и хеш.
